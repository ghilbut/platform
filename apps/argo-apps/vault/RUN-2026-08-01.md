# Vault 초기화 및 복구 자격 증명 실행 기록 — 2026-08-01

## 목적

CPA Kubernetes cluster에 배포한 Vault를 AWS KMS auto-unseal로 처음 초기화하고, root token과 recovery key를 안전하게 인계한다.

root token과 recovery key는 Kubernetes Secret, ConfigMap, Pod 파일 시스템에 저장되지 않는다. `vault operator init`의 표준 출력이 유일한 수령 방법이다. 초기화가 끝난 뒤에는 같은 값을 다시 읽을 수 없다.

## 현재 구성

- Kubernetes context: `cpa`
- Namespace: `vault`
- Vault Pod: `vault-0`
- Seal: AWS KMS (`alias/platform-vault`)
- AWS 인증: CPA ServiceAccount OIDC federation으로 `platform-vault` IAM 역할을 사용
- Recovery key 계획: 5개 생성, 3개 필요

## 초기화 전 확인

아래 명령만 실행한다. Secret의 내용을 출력하지 않는다.

```sh
kubectl --context cpa get namespace vault
kubectl --context cpa -n vault get pod vault-0
kubectl --context cpa -n vault get serviceaccount vault
kubectl --context cpa -n vault exec vault-0 -- vault status
```

마지막 명령의 결과가 다음 조건을 만족할 때만 초기화한다.

- `Seal Type`이 `awskms`이다.
- `Initialized`가 `false`이다.
- `vault-0` Pod가 `Running` 상태다.

`Initialized`가 `true`이면 절대로 `vault operator init`을 다시 실행하지 않는다. 이미 초기화된 Vault는 새 root token이나 recovery key를 출력하지 않는다.

## 초기화와 값 수령

승인된 비밀 보관 담당자가 직접 실행한다. 출력 전체가 root token과 recovery key를 포함하므로 터미널 기록, 화면 공유, CI 로그, 셸 히스토리, 일반 파일로 전달하거나 저장하지 않는다.

```sh
kubectl --context cpa -n vault exec -it vault-0 -- \
  vault operator init \
  -recovery-shares=5 \
  -recovery-threshold=3 \
  -format=json
```

출력 JSON에서 아래 필드를 즉시 수령한다.

- `root_token`: 초기 운영 설정에만 사용할 root token이다.
- `recovery_keys_b64`: 서로 다른 5명의 수탁자에게 한 개씩 인계할 recovery key다.

명령 직후 확인한다.

```sh
kubectl --context cpa -n vault exec vault-0 -- vault status
```

`Initialized`가 `true`이고 `Sealed`가 `false`여야 한다. `Sealed`가 `true`이면 AWS KMS seal 또는 ServiceAccount OIDC federation의 오류를 조사한다. recovery key를 `vault operator unseal`에 사용하지 않는다. 이 구성은 AWS KMS가 Vault를 unseal한다.

## 보관과 후속 조치

- root token은 승인된 비밀 관리 시스템에 보관하고, Kubernetes에는 저장하지 않는다.
- recovery key 5개는 서로 다른 수탁자와 저장 위치에 분리해 보관한다.
- root token으로 OIDC 또는 Kubernetes 인증, 관리자 정책과 관리자 identity를 구성한 뒤 root token을 폐기한다.
- root token을 잃으면 recovery key 3개로 `vault operator generate-root`를 실행해 새 root token을 만든다. 기존 root token을 조회할 수는 없다.

## 실행 전 필요한 결정

아래 정보는 아직 이 저장소에 기록되어 있지 않다. root token과 recovery key를 생성하기 전에 승인받아 이 실행 기록에 추가한다.

1. recovery key 수탁자 5명의 책임자와 개별 보관 위치
2. root token의 승인된 비밀 관리 시스템과 접근 권한자
3. 평문 출력 대신 사용할 수탁자별 PGP 공개키와 root token 수령자 PGP 공개키
4. Vault 초기 운영 인증 방식(OIDC 또는 Kubernetes)과 관리자 identity

PGP 공개키가 준비되면 `vault operator init`에 `-recovery-pgp-keys`와 `-root-token-pgp-key`를 추가하여 수령자 공개키로 암호화된 값을 출력한다.
