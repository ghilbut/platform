# 보안 기준

이 문서는 모든 플랫폼 영역의 관측 접근에 적용하는 공통 보안 기준을 정의한다.

## 접근 원칙

> [!important] 관측 접근
> 모든 관측 정보를 허용하고 민감정보만 거부한다.

관측 접근은 시스템을 이해하고 개발, 운영 및 문제 해결의 판단 근거를 얻는 읽기 작업이다. 리소스
이름과 구성은 보안 경계로 사용하지 않는다. 인증, 권한, 암호화, 네트워크 및 리소스 정책이 변경
작업과 민감정보 접근을 차단한다.

| 분류 | 접근 | 정보와 작업 |
| --- | --- | --- |
| 관측 정보 | 허용 | 이름, 식별자, 경로, 태그, 상태, 구성, 정책, 관계와 토폴로지 |
| 관측 정보 | 허용 | 로그, 추적, 지표, 이벤트, 보안 탐지 결과와 리소스 인벤토리 |
| 관측 정보 | 허용 | 객체와 파일의 위치, 크기, 수정 시각, 버전, 저장 유형과 무결성 정보 |
| 관측 작업 | 허용 | 상태를 변경하지 않는 조회, 검색, 분석, 진단과 권한 시뮬레이션 |
| 민감정보 | 거부 | 비밀번호, 토큰, 개인 키, 비밀값, 세션 정보와 자격 증명 |
| 민감정보 | 거부 | 개인정보와 법률, 계약 및 거버넌스에서 열람을 제한한 정보 |
| 민감정보 | 거부 | 민감정보가 포함된 객체·파일 본문, 상태 데이터, 백업, 데이터 레코드와 메시지 |
| 변경 작업 | 거부 | 생성, 수정, 삭제, 배포, workload 명령 실행, 권한 변경과 다른 역할 수임 |

정보가 서비스, 계정, `bucket`, `database` 또는 `repository`에 저장되었다는 이유로 리소스 전체를
민감정보로 분류하지 않는다. 같은 리소스에서 관측 정보는 허용하고 민감정보를 반환하는 작업만
거부한다.

## 데이터 배치

- 민감정보를 이름, 식별자, 경로, 태그, 상태, 구성, 로그, 추적, 지표, 이벤트와 오류에 저장하지 않는다.
- 관측 정보와 민감정보를 필드나 작업 단위로 분리할 수 없으면 리소스, 계정, `repository` 또는
  `project`를 분리한다.
- 법률, 계약 및 거버넌스 제한은 대상 정보, 책임자와 제한 범위를 문서화한다.
- 새로운 서비스와 리소스는 민감정보를 공개하지 않고 관측 정보를 관측 권한이 있는 사용자와
  자동화에 제공하도록 구성한다.
